# 第一部分：视频里的做法

## 1. 第一步：先把轴吃透（00:52）

素材：**B 站两只攻略视频**（15 秒启动轴、23 秒双循环轴）+ 原作者给的**文字轴**。

但文字轴只是参考：实战里每个动作耗时都不同，视频还可能变速。真正可靠的时钟只有**游戏内的倒计时**。

具体做法是让 AI 读**三个角色的技能全文**，再查**动作帧数据表**，把"这条轴为什么这么打"弄明白。视频举的例子：

- 莫宁地面三段普攻，第一帧分别给 **20 / 43 / 37 点回路**：先打 A1、A2 攒到 63，回来补一下 A3 正好 100，才能升空；
- 琳奈要攒满协奏（约 120）才能蓄力，蓄满后三次折跃把流光用完；
- 爱弥斯要靠大招 + 两发光翼凑够共鸣率，才能放出 R2。

**这一步的产出不是代码，是"资源账本"**：每个角色的资源来自哪几招、每招给多少、阈值是多少、差一点会发生什么。后面所有判定条件都从这里来。

## 2. 第二步：把视频拆成时间表（01:50）

逐帧看视频，记录每个动作发生在第几秒。视频里的轴一圈 **25 秒、几十个节点**：

> R2 → 点完进击兵 → 变奏琳奈 → 琳奈 1 → 切莫宁 → 爱弥斯切回人形 → ……

再对照帧数据，判断**每个动作能不能被打断、最早什么时候能接下一招**。

**这张表就是写代码的蓝本。** 后面代码里的每一个等待时长、每一个"提前量"，都来自这张表。

## 3. 第三步：写成代码，并在屏幕上找锚点（02:16）

程序看不见角色在做什么动作，**只能按时间按键**。可纯靠定时会越跑越歪——怪的位置、网络延迟，都会让动作时长变化。

所以要在屏幕上找**锚点**：

- 回路条亮了几格；
- 技能图标有没有变；
- 跳跃键是不是换成了普通跳；
- 协奏环有没有闭合。

**读到了，再按时间往下走。** 例子：莫宁的回路条空中是白色格子、落地后变成橙色格子；AI 写了个函数从左往右数点亮的格子，就知道当前积攒了多少。

锚点的工程要求（03:00）：

> 每个锚点都按 4K 坐标换算，再拿 2K 截图和缩到 1080P 的同一帧各跑一遍，**读数一致才算数**。

即：所有坐标用比例而非绝对像素，并在多种分辨率下验证同一帧读数一致。

## 4. 第四步：先干跑，再上实机（03:10）

AI 写了一个**假游戏**：按资源规则模拟三个角色，把整条轴空跑一遍。

关键设计（03:22）：

> **每一条保底分支都配一个"故意失败"开关**——能量不够、按键被吞、角色被挤开。
> 保底代码平时根本跑不到，不故意制造失败，就等于没测过。

这句话是整个流程里最值钱的一句：**保底分支必须被测到**，否则线上第一次触发就是事故。

## 5. 第五步：实机跑、录屏、翻日志（03:34）

分工：人负责"看和描述"（这里慢了、那里没放出来），AI 负责把录屏和日志对上时间、逐帧测量、找真正的原因。

视频里这条轴来回改了 **40 多轮**，作者挑了 4 个最典型的：

### 案例一：莫宁回路不满 → 根因是切人慢了 0.06 秒（03:57）

- 现象：循环里莫宁 A1、A2 有时没打到位，后面切回来回路不满，升空失败。
- AI 先加"读到 A2 再切"的判定，问题还在。
- 人看出来：**莫宁一出场就被怪挤到了天上**。
- 逐帧测量：琳奈一出手后，我们 **0.23 秒**才切到莫宁，作者只用 **0.17 秒**。
- 后果链：差这 0.06 秒 → 莫宁在怪身上出场被顶飞 → 下一刀变成下落攻击（不给回路）→ 落地接的是 A3 → 20+37=57，正好对上读到的 57。
- 修复：**出手即切** + 回路不到 63 就继续打。之后每圈稳定读到 0.62。

> 教训：症状在 A 角色，根因在**上一个角色的退出时机**。

### 案例二：琳奈大招能量差一点，程序卡死（05:03）

- 现象：能量偶尔差一点，代码卡住；人手动补一个大招，整圈反而全乱。
- 翻日志发现：**"能不能放大招"的读屏会误报**——第一帧说能放，按了半秒没反应，再读说不能，程序就放弃，卡在原地等协奏；而人手动按出的大招让技能栏消失，程序还在傻等，切人又撞进大招演出。
- 修复：
  1. **能量读数只决定"什么时候开始按"，不决定"放弃"**；
  2. R 和普攻交替按，差的那点能量靠普攻补；
  3. **技能栏一消失就算大招放出去了，不管是谁按的**；
  4. 4 秒还放不出来就跳过这一圈，绝不卡住。

> 教训：状态判定要设计"终态"（技能栏消失），不能只依赖"开始条件"（能量够）。

### 案例三：协奏"感觉满了"，程序却多打一下（05:54）

- 人觉得天机炮之后协奏已经满了，程序还要多打一下。
- AI 把录屏里的**协奏环逐帧放大**，测环被填满的角度：程序读到满的那一帧，**正好是环真正闭合的那一帧**。
- 在那之前的一秒多，环在 3 点钟方向其实还缺一小截——因为**伤害要出手后一秒多才到账**。
- 结论：那一下不是判断慢，是真的还没满。
- 真正的优化点在前面：以前等莫宁大招演完才按住攻击，天机炮还要再等 0.4 秒起手；现在**演出时就提前按住，演完立刻出炮**。

> 教训：先证明"到底满没满"，再谈优化；优化要找**前置动作的空档**，不是压缩判定。

### 案例四：把 E1→E2 缩短 0.4 秒，反而打崩（06:34）

- 人要求循环里莫宁 E1 和 E2 之间缩短 0.4 秒。
- AI 照做 → E2 出太早，回路条只剩 0.44，后续关键招式（视频里叫"天机炮"）直接没了。
- 回头对照教学视频：作者的 E 冷却走到 **15.6 左右**才出 E2，我们是 15.8；但**之前慢的那几圈是 15.2**，原因是多了一个"E2 能不能放"的判定。
- 对表方法：统一标准，**都看 E2 图标变成 25.0 的那一帧**，作者 15.4，我们 15.8。
- 帧数据解释：某类浮游炮的后两发要到**第 36 帧**才生成，E2 放早了会把它们打掉。
- 最终：等待回到 0.45 秒、去掉那个判定，**每圈都是 15.4**。

> 教训：**AI 也会出错，你的眼睛和对游戏的理解是最后一道关**；对表必须同一标准、同一帧。

## 7. 视频补充的 5 个坑（07:36）

1. **配置里的闪避键按下去不打断跳跃**；战斗中的闪避实际是**鼠标右键**；
2. 琳奈的第三段按了不一定出，**要看跳跃键的图标换没换**；
3. **10 毫秒的点击会被游戏吞掉**——必须打出来的普攻要按住几十毫秒；
4. **协奏差不多满就切，切过去就不是变奏入场**（必须等真满）；
5. 以上每个坑都是**从实机录屏里看出来的**。

以及环境前提（09:03）：分辨率、帧率、网络延迟、角色链数、声骸配置都会影响时机，**同一份代码未必在每台电脑上跑通**。

# 第二部分：在 ok-ww 上落地

> 视频讲的是通用方法（作者做的是 ok-ww 的自定义队伍轴）。下面把它映射到 ok-ww v1.4.81 的真实结构。

## 8. 轴在 ok-ww 里是什么

### 8.1 运行链路

`src/task/AutoCombatTask.py`：

```python
while self.in_combat():
    self.get_current_char().perform()      # 当前角色打自己的窗口
```

`perform()` 是壳，执行的是角色类的 `do_perform()`；打完后角色自己调 `switch_next_char()` 交棒。

**交棒给谁不由脚本写死**，由 `BaseCombatTask._choose_switch_target()` 投票：

1. 每个候选角色算 `get_switch_priority()`（`NO / LOW / NORMAL / HIGH / MUST`）；
2. 取最高一档；
3. 有变奏入场（`has_intro`）时按「没 buff 的辅助 → 主C → 副C → 奶」；
4. 没入场时按 `buff_time` 剩余、角色定位、切换 CD 选；
5. 奶妈满协奏有 16s 锁（`HEALER_FULL_CON_SWITCH_LOCKOUT`），防止奶妈抢变奏。

所以「轴」= **每个角色在自己窗口内做什么 + 用优先级禁掉不该发生的切人**。

### 8.2 队伍代码包（视频做的就是这种）

```
<ok-ww working>\configs\custom_teams\Aemeath__Linnai__Mornye\
├── team.json
├── Aemeath.py
├── Linnai.py
├── Mornye.py
└── *.import.py        # 可选，code_mode = import 时生效
```

- 目录名 = 三个**类名**按字母序 + `__`；注意类名和英文显示名不一样（`Linnai` 显示为 `Lynae`、`ShoreKeeper` 显示为 `Shorekeeper`、`Xiangliyao` 显示为 `Xiangli Yao`）。**目录与 py 文件名用类名，`team.json` 的 `team` 字段用英文显示名**，这里最容易搞混。
- `team.json`（`src/char/CustomCharLoader.py` 约定）：

```json
{
  "name": "爱琳莫5R2",
  "description": "配置条件、站位、已知问题写这里",
  "author": "你的ID",
  "version": "1.0.0",
  "team": "Aemeath, Lynae, Mornye",
  "code_mode": "import"
}
```

- `team` 必须是**英文显示名、字母序、逗号分隔**；导入时 `inspect_team_archive` 会校验字段非空、顺序正确、zip 里**恰好三个 py + team.json**。
- `code_mode`：`import` 用 `.import.py` 副本，`builtin` 用内置代码；切换是整队一起。
- 保存时 `_validate_character_code` 校验：**文件名 = 类名、继承 `BaseChar`、能编译**，失败回滚。
- 文件按 mtime + size 缓存，**保存即热重载**（只影响下一次战斗，不会中途换类）。

### 8.3 角色怎么被认出来

`CharFactory.get_char_by_pos()` 用头像模板匹配（阈值 0.6），**三个角色全识别成功**后 `apply_team_char_classes()` 才加载自定义类。日志里出现 `could not find char` 就说明识别失败，轴会退回内置逻辑（表现为"突然变傻"）。

## 9. 六步法 → ok-ww 操作对照

| 视频步骤 | 在 ok-ww 里怎么做 |
|---|---|
| 1. 吃透轴 | 读 `src/char/<角色>.py` 内置实现 + 官方/社区动作帧数据；把资源账本写成注释或文档 |
| 2. 拆时间表 | 录屏 60fps 逐帧；表里每个节点标注：动作、耗时、判定锚点、可打断性 |
| 3. 写代码 + 锚点 | 模板匹配 `task.find_one('模板名', threshold=...)`；颜色/格子 `task.calculate_color_percentage` + `task.box_of_screen_scaled(...)`；OCR 用 `task.ocr(...)` |
| 4. 假游戏干跑 | ok-ww **没有**内置模拟器，自己写 stub task（见 9.1） |
| 5. 实机迭代 | `logs/ok-script.log` + debug 截图 + 每次实机录屏；改完先干跑 |

### 9.1 用 stub task 做"假游戏"（对应视频第四步）

ok-ww 的角色类只依赖 `self.task` 的少数方法，可以造一个假 task，把画面状态换成脚本控制的变量：

```python
class FakeTask:
    def __init__(self):
        self.t = 0.0
        self.con = 0.0            # 协奏值
        self.forte = 0            # 回路格数
        self.actions = []
        self.visible = set()      # find_one 能命中的模板名，由用例控制
        self.in_combat = True

    # 被角色代码调用的接口，只实现用到的那几个
    def click(self, *a, **k):         self.actions.append("click")
    def send_key(self, key, *a, **k): self.actions.append(key)
    def wait_until(self, cond, time_out=0, post_action=None):
        step = 0.05
        waited = 0.0
        while waited < time_out:
            if cond(): return True
            if post_action: post_action()
            self.t += step; waited += step   # 资源按规则推进
        return False
    def next_frame(self): self.t += 0.016
    def find_one(self, name, **k): return name in self.visible   # visible 由用例控制
    def in_team(self): return True, 0, 3
```

然后直接 `MyChar(fake_task, 0).do_perform()`，断言动作序列、循环次数、超时后是否走保底。

**必须覆盖的"故意失败"场景**（对应 03:22）：能量差一点、技能栏不消失、按键被吞（`click` 无效）、角色被挤开（锚点读不到）、协奏始终不满。

## 10. 代码模板

### 10.1 一个上场窗口

```python
import time
from src.char.BaseChar import BaseChar


class MyChar(BaseChar):
    """状态只放实例字段：开关自动战斗会重建实例，天然等价于"这一场战斗"。"""

    def do_perform(self):
        if self.has_intro:
            self.continues_normal_attack(1.2)      # 入场固定动作

        self.click_echo(time_out=0)                # 召唤型声骸用 time_out=0

        start = time.time()
        while self.time_elapsed_accounting_for_freeze(start) < 8:   # 窗口必须有上限
            if self.is_con_full():
                break
            if self.click_liberation():
                continue
            if self.is_forte_full() and self.heavy_click_forte(self.is_mouse_forte_full):
                continue
            if not self.click_resonance(time_out=0)[0]:
                self.click()
            self.sleep(0.05)

        self.switch_next_char()
```

### 10.2 强制切人顺序

内置 `Mornye` / `Linnai` 就是用优先级把"莫宁离场必须切琳奈"写死的：

```python
from src.char.BaseChar import SwitchPriority

def get_switch_priority(self, current_char=None, has_intro=False, target_low_con=False):
    if current_char and current_char.char_name == "char_moning":
        return SwitchPriority.MUST
    return super().get_switch_priority(current_char, has_intro, target_low_con)
```

### 10.3 用读屏做"资源账本"（对应视频第三步）

- 数格子（莫宁回路条）：`task.box_of_screen_scaled(...)` 划出每格 + `calculate_color_percentage` 逐格判断；
- 图标是否变化（强化 E / 跳跃键）：`task.find_one('aemeath_e1', threshold=0.7)` 一类模板；
- 协奏环是否闭合：测环的角度/面积，而不是看一个点；
- 所有区域坐标用**比例**定义，1080p / 2K / 4K 各验一次**同一帧读数一致**。

### 10.4 五条硬规则

1. **每个 while 必须有超时**（框架只给 `click_resonance` 兜 15s，自己写的没人管）；
2. **动画时间用 `time_elapsed_accounting_for_freeze(start)`**（大招/入场动画期间游戏时间冻结，直接 `time.time()` 会让下一轮永远慢半拍）；
3. **不要裸 `sleep` 等状态**，用 `task.wait_until(cond, time_out=..., post_action=...)`；
4. **判定要有终态兜底**（如"技能栏消失"），不能只依赖开始条件；
5. **保底要能触发**：被打断/击飞后尽快攒满协奏离场，而不是死等原流程。

### 11.3 失败定位表

| 现象 | 先查 |
|---|---|
| 完全不攻击、反复锁敌 | 主声骸没装 / 目标模板不匹配 |
| 切人顺序乱 | 日志 `switch_next_char` 行；`get_switch_priority` 是否被覆盖 |
| 技能按了没反应 | 键位配置（`configs/Game Hotkey.json`）/ 技能在 CD / 10ms 点击被吞 |
| 每轮越来越慢 | 用了 `time.time()` 而不是 freeze-aware 计时；窗口超时太长 |
| 启动轴时好时坏 | 入场判定晚了（`has_intro` / `check_outro()`）；给 `wait_intro` 加超时 |
| 只在某些 BOSS 失败 | 转火/飞天/击飞，是轴的边界，需要保底或换开局目标 |
| 轴"突然变傻" | 角色识别失败退回内置；查 `could not find char` |
