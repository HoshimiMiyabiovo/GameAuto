## 1. 项目定位

**Game Auto** 是一个 Windows 桌面游戏自动化助手（Python 3.13+，大量 Win32 API），核心职责是：

1. **编排与监控**：按配置顺序串行启动多款二次元游戏及其第三方自动化脚本（BetterGI / March7th / OneDragon / ok-ww / ok-ef / ok-nte / whimbox 等），监控日志、检测报错卡死、自动重试；
2. **每日签到**：米游社（原神/星铁/绝区零）、库街区（鸣潮）、塔吉多（异环）、森空岛（终末地）签到，token 失效自动重登/刷新；
3. **每日进度聚合**：通过官方/社区 API + 脚本日志解析，判定每款游戏当天日常是否真正完成（活跃度/委托/实训等口径），驱动跳过、重试与统计；
4. **视觉流程自动化**：自研「图像模板 + OCR」流程引擎，覆盖启动器点击、游戏内日常（白荆回廊全套）、月度商店兑换、薅羊毛（MiniMax/WorkBuddy/TRAE/Qoder/TeleAgent/码道/AStudio/DuMate/商汤小浣熊 九家每日福利）等；
5. **抽卡分析**：多数据源导入统一落 SQLite，产出保底/卡池/五星历史分析；
6. **辅助能力**：邮件日报、运行完自动关机、Web 远程查看面板、点击序列录制回放、失败取证、脚本管理（第三方脚本一键安装/换血更新）、磁盘管理、AI 对话史汇总与检索。

本项目**不内置游戏脚本本身**，只负责调度这些第三方工具并补齐它们没覆盖的环节（签到、进度判定、商店采购等）。

一条龙跑批的完整数据流：

```
用户/定时任务 → UiBridge.run_task_batch
  → startup_sign_runner（启动前签到，双写 tracker + app_config）
  → 逐游戏：维护预检（官方公告窗口跳过+动态补跑）→ 今日已完成跳过
  → _run_single_task：
      ├─ 独立虚拟任务（XM/CJ/薅羊毛/Qoder）→ background_template_runner
      ├─ ok 系脚本 → run_ok_script_once + 日志监控
      │   （鸣潮另有 module_mode 常驻 headless runner 链路）
      └─ 其余 → automation_controller.execute_task
            （清理残留 → prelaunch_flow → 拉脚本 → _monitor_game 循环监控）
  → 月度/周常钩子：日常跑完后 _run_pending_monthly_flow 按游戏档案触发
  → 事后判定：bettergi/starrail/zzz 专用改判 + _verify_script_log_result 日志复核
  → daily_progress_tracker 落库 → daily_checker API 实时进度补全
  → 失败统一 8s 后重试一次
  → 收尾（finally 兜底）：邮件日报 → 自动关机 → UI 复位
```

## 5. services/ 服务层

### 核心服务

- **daily_progress_tracker.py** — 每日进度 SQLite 落库。`daily_progress` 表以 `UNIQUE(date_key, game_key, task_key)` UPSERT；日期分界凌晨 4 点（RESET_HOUR）。核心是 `GameDailyRecord.completion_state()` 四态裁决：`completed / unknown（关键计数未刷新）/ failed / pending`，优先级 KEY_STATUS_TASKS（纯状态：nte「日常领取」、zzz「活跃度奖励」、nikki「朝夕心愿」）→ KEY_PROGRESS_TASKS（计数：wuwa「今日活跃」、genshin「每日委托」、endfield「日活跃」、baijing「活跃度」等，必须在 extra 带 current/total）→ is_all_success → has_failed。统计完成率时分母排除 unknown 天。测试进程禁写生产库（`is_test_process() and is_production_data_path()` 双条件，2026-11-22）。
- **startup_sign_runner.py** — 启动前签到调度。按开关依次执行五类签到；**双写铁律**：既写 tracker（`sign_` 前缀任务），也原子写回 app_config.json 的 `last_sign_date/status/message`（DailyView 只读后者）；同一天 failed 不得覆盖 success/already（2026-11-21 防降级）。
- **daily_checker.py** — 不在 services，在 clients（见 §7），此处指其角色：实时 API 查询各游戏关键进度并落库。
- **dependency_manager.py** — 启动依赖自检，**只检查、不安装**（2026-10-29 起）。运行时解析 requirements.txt 得到 import 名→pip 包名映射（例外表 `IMPORT_NAME_BY_PACKAGE`，`REQUIRED_PYTHON_PACKAGES` 是推导值）；**新增依赖只改 requirements.txt**，安装统一走 setup_deps.bat（普通权限，uv + requirements.lock --no-deps 精确回放）。禁止恢复启动时提权 pip install。
- **email_reporter.py** — SMTP 日报；授权码经 Windows DPAPI 加密落盘；`build_daily_report` 支持"发信前实时查询"标注（防发缓存数据）。
- **game_update_calendar.py** — 拉官方更新公告（米哈游三家 + 鸣潮 CMS + 异环官网 + 暖暖 API）解析维护窗口与开服时间，6h 缓存（`data/cache/game_update_calendar.json`）；支撑"维护跳过 + 到点动态补跑"（队列 `data/cache/update_retries.json`）。
- **credential_store.py / secure_store.py** — 敏感凭据两级存储：token/did 存 workflow_db `credentials` 表（`dpapi:` 前缀密文）；app_config.json 中的敏感键由 manager.py `_walk_encrypt` 加密；DPAPI 解密失败返回空串走"未配置"分支。
- **hang_watchdog.py** — 主线程卡死看门狗：QTimer 2s 心跳，>15s 冻结由 daemon 线程 faulthandler 转储全线程栈到 `data/logs/watchdog_main_thread.log`。
- **task_heartbeat_watchdog.py** — 任务线程心跳看门狗（2026-10-15 蓝屏复盘产物）：`_monitor_game` 每轮 beat()，>600s 无心跳 dump 栈到 `data/logs/watchdog_task_heartbeat.log` 并注入止损回调（置停止 + 杀进程树）。
- **instance_lock.py** — msvcrt 文件锁防多开；维护执行器另取 `acquire_aux_lock("maintenance")` 互斥；**instance_lock + 原子写 + WAL** 是并发三件套。
- **launch_task_catalog.py** — 独立虚拟任务目录（4 个）与执行顺序合并、已删任务 key 过滤。
- **script_tool_installer.py / script_version_check.py** — 脚本管理页后端：ok-ww/ok-ef/ok-nte/March7th/BetterGI 一键下载安装与换血式更新（sha256 校验、进度可取消、运行中拒绝），安装根默认 `data/script_tools/`。
- **ai_history_refresh.py** — AI 对话史全链编排（本地抓取 → F 盘聚合 → 拷回 → RAG 索引），单飞闸 + 双锁，GUI「每日进度」页一键触发；口径见 conventions/09。
- **utils.py** — 含关键的 `read_file_with_timeout`（日志读取带超时，防 IO 卡死钉住监控线程）。
- 其它：logging_setup（QueueHandler 队列化写盘）、disk_usage（磁盘管理页）、game_shot_service（截图）、popup_dismisser（弹窗清理）、network_preflight、mem_reduct_detect、stamina_configs/（第三方刷本配置适配器）。

## 6. runtime/ 执行层

### 调度与进程管理

- **automation_controller.py**（核心类 `AutomationController`）— 任务级进程管家。`execute_task()`：清理残留进程树 → `_run_prelaunch_flow`（如 WuwaLauncher）→ 拉起脚本 → `_monitor_game` 监控循环：等游戏进程快照 → 轮询报错监控提前止损 → 跟踪 PID/窗口可见性 → 焦点守护 → 收尾返回 `(success, duration, reason)`。内置任务线程心跳 beat 与米哈游维护窗口快速跳过；`_ok_ww_daily_completed()` 用当天日志兜底"跑太快被误判失败"。
- **task_batch_runner.py** — 「一条龙大脑」。`run_task_batch` 串行执行：启动前签到 → 每游戏跳过今日已完成（`_is_game_script_done_today`：脚本行全成功之外还要求 completion_state ∈ {completed, unknown}）→ `_run_single_task` 分派 → 月度/周常钩子（`_run_pending_monthly_flow`，按 games/ 档案的 monthly_flow）→ 事后判定三兄弟（`_apply_bettergi_verdict` / `_apply_starrail_score_verdict` / `_apply_zzz_activity_verdict`）+ `_verify_script_log_result` 日志复核（只 success→failed 单向）→ 失败统一 8s 重试一次。FailSafeAborted 在此收口为优雅终止整批。
- **process_supervisor.py / window_detector.py** — 进程发现/查杀（整棵进程树）与窗口-PID 关联。
- **okww_module_session.py** — 鸣潮模块化链路：常驻 headless ok-ww runner 会话管理（`module_mode.enabled=true` 时不再拉起 ok-ww.exe）。

## 9. UI 层

### 桌面 GUI（PySide6 + QML + PyHuskarUI）

- **app/gui.py** 内联初始化（QApplication + HusApp.initialize + Engine + Bridge，不走跨模块导入链——`python -m` 模式下跨模块导入会导致 QML 加载失败）；已设置 WebUI 账号时启动 5s 后后台线程拉起 WebUI（未设置账号不启动）；`HangWatchdog` 全程守护。
- **ui/bridge.py（UiBridge）** — Python↔QML 唯一枢纽，已拆分（2026-10-29 基线）：bridge.py 只保留核心状态、Qt 属性/信号（48 个 Signal）与事件分发（5 个 @Slot）；各视图 `@Slot` 实现在 **ui/bridge_views/ 8 个 mixin**（automation / click_sequence / daily / gacha / disk_manager / scheduler / setup / tool_manager，全桥共 111 个 @Slot），领域逻辑在 **ui/bridge_backends/**（daily_progress / gacha 等）。新逻辑按视图放对应 mixin 或 backend，不要再往 bridge.py 堆。后台线程经 Qt 排队信号自动回主线程。**带返回值的 @Slot 必须声明 `result=` 类型**，否则 QML 拿到 undefined 且不报错（历史事故）。
- **Main.qml** — HusWindow 1400×900 + 侧边栏 + 内容区 **14 个异步 Loader**（`active: ... || xxEverLoaded` 门控首屏只加载当前页）；重页面（daily/gacha/nikki/wuwa/staminaConfig）距最后切页超过 `viewReleaseDelayMs`（默认 3 分钟）且非运行中时延迟释放回收内存（2026-11-01，见 conventions/03）——因此每个视图的后台线程必须 daemon + 网络带 timeout。
- **凭据输入必须用 `components/CredentialInput.qml`**（默认掩码 + 显隐按钮），禁止裸 HusInput 收 token/cookie。
- **ui/flet_app.py**（~6900 行）旧 Flet UI 已暂停维护，`run_flet_gui` 无 caller，仅作回退。

### WebUI（ui/webui/，FastAPI，仅绑 127.0.0.1:60171）

五个路由模块（auth/automation/daily/wool/clickseq）+ 原生 JS 单页；PBKDF2 鉴权（20 万轮，DPAPI 落盘）+ 12h token；`/api/logs` 增量游标 + WebSocket 日志流；同进程经 `get_active_bridge()` 读 GUI 状态、共享 `AutomationController` 单例。定位是远程查看/触发的 GUI 子集；未设置账号不启动。

## 10. 鲁棒性设计（事故驱动的防护清单）

| 防护 | 触发场景 | 机制 |
|---|---|---|
| 日志队列化 | 盘 IO 卡住不阻塞业务线程 | GameAutomation logger 只挂 QueueHandler，QueueListener 消费写盘 |
| 读超时 | USB/机械盘读日志挂起 | `read_file_with_timeout`（默认 10s），超时放弃本轮下轮重试 |
| 任务心跳看门狗 | 任务线程卡死（主线程心跳正常时旧机制无感） | >600s 无 beat → dump 栈 + 置停止 + 杀进程树 |
| 主线程看门狗 | GUI 冻结 | >15s → faulthandler 全线程栈到 watchdog_main_thread.log |
| pyautogui fail-safe 收口 | 鼠标在 (0,0) 触发 FailSafeException | `_pyautogui_click_guarded` 转中文异常，批次优雅终止不崩溃 |
| UIPI 权限护栏 | 本程序普通权限 + 游戏管理员权限 → 点击静默无效 | `run_flow` 预检双方 TokenElevation，直接报可行动错误 |
| OCR 全屏回退禁令 | 窗口不可用时 OCR 拍到桌面/日志文件误命中 | 传了 hwnd 取不到区域 → 返回空结果重试，绝不退化全屏 |
| 日志污染拦截 | 截图里出现 auto_runner.log 文字被当成界面文字 | `_check_log_contamination` 剔除命中日志特征模式的 OCR 条目 |
| 收尾 finally 兜底 | 任务异常穿透导致不发邮件不关机 | 邮件/关机/状态复位全在 bridge_views/automation 的 `_run_automation_backend` finally |
| 长等待可中断 | 用户点停止后 45s 才生效 | 所有等待传 `stop_check`，轮询粒度 0.25s（个别旧路径未接线） |
| 单实例锁 | 多开竞争 | msvcrt 文件锁，崩溃由 OS 释放；维护执行器另取互斥锁 |
| 失败取证 | "步骤没匹配上"无法回看 | record_failure 截图+OCR→flow_failures 表，`tools/flow_failure_report.py` 聚合 |
| optional 假成功防线 | optional 步骤找不到元素直接跳过报 ✅ | 规则：optional 点击后必须跟非 optional 验证步；末步日志核验 fail-closed |
| 维护日动态补跑 | 版本更新维护空跑 | 官方公告解析窗口→跳过；开服+5min 动态补跑队列（最多 3 次） |
| 测试进程禁写生产库 | 套件假 hwnd 污染失败记录/日报/月度门控 | `is_test_process() and is_production_data_path()` 双条件拒写（2026-11-22） |

## 13. 依赖

唯一人工清单是 `requirements.txt`（psutil / pyautogui / opencv-python / Pillow / PySide6 锁 `>=6.8.3,<6.9` + pyhuskarui / flet / pytesseract / genshin / browser-cookie3 / qrcode / rsa / pycryptodome / pynput / openpyxl / fastapi / uvicorn / websockets / pydantic / **onnxruntime-gpu**（主 OCR，CPU 版会静默降级）/ shapely / pyclipper / windows-capture / numpy / ruamel.yaml / py7zr / backports.zstd）；`requirements.lock` 是已验证环境（Python 3.13）的精确快照。

- 安装统一 `setup_deps.bat`（普通权限，uv + lock --no-deps 回放）；启动时 `dependency_manager` **只检查不安装**，缺包提示跑 setup_deps.bat。**新增依赖只改 requirements.txt**（import 名例外才登记 `IMPORT_NAME_BY_PACKAGE`），然后本机验证并 `tools/refresh_requirements_lock.py` 刷新锁文件。
- Tesseract：Python 包 pytesseract 随依赖必装；`tesseract.exe` + chi_sim 中文包**可选**，仓库不含二进制（`tools/tesseract/` 已 gitignore，本机另放）。
- PyHuskarUI 0.6.1 与 Qt 6.10+ 不兼容（ParallelAnimation 报错），故 PySide6 锁 `>=6.8.3,<6.9`；升级后需清 `%LOCALAPPDATA%/GameAuto/` 的 QML 缓存（*.qmlc）。

## 14. 测试与诊断

- **回归测试**在 `tests/suite_*.py`（140+ 套，2026-10-29 从 `artifacts/test_*.py` 迁入，日期后缀不变），`tests/test_suites.py` 逐个子进程隔离跑；新增套件按 `suite_*.py` 命名自动纳入并登记 `tests/ci_suites.txt`。默认 `pytest tests -q` 跑 fast 档（约 2 分钟，结尾打印最慢 10 项）；真机/慢套件全量显式 `GAMEAUTO_TEST_TIER=full`。覆盖：月度兑换、白荆全套、薅羊毛、Qoder 核验、OCR 防护、UIPI 护栏、各启动器、看门狗、判定口径等。改对应模块后必须跑同名回归。

## 15. 开发约定速查（详见 AGENTS.md 与 docs/conventions/）

1. **改代码前写小计划**：目标文件/符号、假设、第一步验证；首个实质编辑后立刻跑最窄验证（py_compile / 对应回归）。
2. **新增依赖只改 requirements.txt**（单一来源），本机验证后刷新 requirements.lock；启动只检查不安装。
3. **新 UI/数据流写 GameAutomation logger**，不落明文凭据。
4. **解析器产出必须带 `extra={current,total}` 且有落库路径**，否则统计永远拿不到。
5. **判定任务名必须与数据源精确一致**（zzz 是「活跃度奖励」不是「活跃度」）。
6. **`@Slot` 带返回值必须写 `result=`**；凭据输入必须用 CredentialInput；新 Slot 按视图放 bridge_views mixin，不堆 bridge.py。
7. **`_connect()` 是 contextmanager**；WorkflowDB 保持 WAL；禁止裸调 `pyautogui.click`；app_config 读改写必须走 manager 锁内入口。
8. **optional 步骤后必须有非 optional 验证**；日志核验 fail-closed，绝不假成功。
9. **不硬编码绝对路径**（用 settings/paths.py）；抽卡数据一律走 SQLite；运行时数据一律放 data/。
10. **新建 Electron 应用流程前先测模板误命中再定阈值**（生效阈值 = 列表最小值）。
11. **驱动游戏内流程的任何脚本必须与 GUI 同权限（管理员）运行**。
12. 数值类结论（完成度/活跃度）必须实跑 API 或查库取证，禁止凭代码推断。
13. **新增游戏只加 games/ 档案模块并 register()**，不再手改 settings/bridge/批处理/更新日历的映射表。
14. **每次改动在 docs/changelog.md 追加一行**；根目录禁堆临时产物，用完即删。
