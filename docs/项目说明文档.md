# Game Auto 项目说明文档

> 更新日期：2026-10-25。本文是面向「想整体理解这个项目的人」的全景说明；日常开发避坑约定见根目录 `AGENTS.md`，面向用户的功能简介见 `README.md`。

---

## 1. 项目定位

**Game Auto** 是一个 Windows 桌面游戏自动化助手（Python 3.10+，大量 Win32 API），核心职责是：

1. **编排与监控**：按配置顺序串行启动多款二次元游戏及其第三方自动化脚本（BetterGI / March7th / OneDragon / ok-ww / ok-ef / ok-nte / whimbox 等），监控日志、检测报错卡死、自动重试；
2. **每日签到**：米游社（原神/星铁/绝区零）、库街区（鸣潮）、塔吉多（异环）、森空岛（终末地）签到，token 失效自动重登/刷新；
3. **每日进度聚合**：通过官方/社区 API + 脚本日志解析，判定每款游戏当天日常是否真正完成（活跃度/委托/实训等口径），驱动跳过、重试与统计；
4. **视觉流程自动化**：自研「图像模板 + OCR」流程引擎，覆盖启动器点击、游戏内日常（白荆回廊全套）、月度商店兑换、薅羊毛（MiniMax/WorkBuddy/TRAE/Qoder 每日积分）等；
5. **抽卡分析**：多数据源导入统一落 SQLite，产出保底/卡池/五星历史分析；
6. **辅助能力**：邮件日报、运行完自动关机、Web 远程查看面板、点击序列录制回放、失败取证。

本项目**不内置游戏脚本本身**，只负责调度这些第三方工具并补齐它们没覆盖的环节（签到、进度判定、商店采购等）。

一条龙跑批的完整数据流：

```
用户/定时任务 → UiBridge.run_task_batch
  → startup_sign_runner（启动前签到，双写 tracker + app_config）
  → 逐游戏：维护预检（官方公告窗口跳过+动态补跑）→ 今日已完成跳过
  → _run_single_task：
      ├─ 独立虚拟任务（XM/CJ/薅羊毛/Qoder/月度兑换）→ background_template_runner
      ├─ ok 系脚本 → run_ok_script_once + 日志监控
      └─ 其余 → automation_controller.execute_task
            （清理残留 → prelaunch_flow → 拉脚本 → _monitor_game 循环监控）
  → 事后判定：bettergi/starrail/zzz 专用改判 + _verify_script_log_result 日志复核
  → daily_progress_tracker 落库 → daily_checker API 实时进度补全
  → 失败统一 8s 后重试一次
  → 收尾（finally 兜底）：邮件日报 → 自动关机 → UI 复位
```

## 5. services/ 服务层

### 核心服务

- **daily_progress_tracker.py** — 每日进度 SQLite 落库。`daily_progress` 表以 `UNIQUE(date_key, game_key, task_key)` UPSERT；日期分界凌晨 4 点（RESET_HOUR）。核心是 `GameDailyRecord.completion_state()` 四态裁决：`completed / unknown（关键计数未刷新）/ failed / pending`，优先级 KEY_STATUS_TASKS（纯状态：nte「日常领取」、zzz「活跃度奖励」、nikki「朝夕心愿」）→ KEY_PROGRESS_TASKS（计数：wuwa「今日活跃」、genshin「每日委托」、endfield「日活跃」、baijing「活跃度」等，必须在 extra 带 current/total）→ is_all_success → has_failed。统计完成率时分母排除 unknown 天。
- **startup_sign_runner.py** — 启动前签到调度。按开关依次执行五类签到；**双写铁律**：既写 tracker（`sign_` 前缀任务），也原子写回 app_config.json 的 `last_sign_date/status/message`（DailyView 只读后者）。
- **daily_checker.py** — 不在 services，在 clients（见 §7），此处指其角色：实时 API 查询各游戏关键进度并落库。
- **dependency_manager.py** — 首次启动依赖自检 + 清华镜像自动 pip 安装；`REQUIRED_PYTHON_PACKAGES` 是 import 名→pip 包名映射，**新增依赖必须同步登记**。
- **email_reporter.py** — SMTP 日报；授权码经 Windows DPAPI 加密落盘；`build_daily_report` 支持"发信前实时查询"标注（防发缓存数据）。
- **game_update_calendar.py** — 拉官方更新公告（米哈游三家 + 鸣潮 CMS + 异环官网 + 暖暖 API）解析维护窗口与开服时间，6h 缓存；支撑"维护跳过 + 到点动态补跑"。
- **credential_store.py / secure_store.py** — 敏感凭据两级存储：token/did 存 workflow_db `credentials` 表（`dpapi:` 前缀密文）；app_config.json 中的敏感键由 manager.py `_walk_encrypt` 加密。
- **hang_watchdog.py** — 主线程卡死看门狗：QTimer 2s 心跳，>15s 冻结由 daemon 线程 faulthandler 转储全线程栈到 `logs/watchdog_main_thread.log`。
- **task_heartbeat_watchdog.py** — 任务线程心跳看门狗（2026-10-15 蓝屏复盘产物）：`_monitor_game` 每轮 beat()，>600s 无心跳 dump 栈到 `logs/watchdog_task_heartbeat.log` 并注入止损回调（置停止 + 杀进程树）。
- **instance_lock.py** — msvcrt 文件锁防多开；**instance_lock + 原子写 + WAL** 是并发三件套。
- **launch_task_catalog.py** — 独立虚拟任务目录与执行顺序合并。
- **utils.py** — 含关键的 `read_file_with_timeout`（日志读取带超时，防 IO 卡死钉住监控线程）。

### 日志解析器（脚本日志 → 结构化任务 → 落库）

| 解析器 | 解析对象 | 关键口径 |
|---|---|---|
| bettergi_daily_parser | BetterGI `better-genshin-impact*.log` | 委托奖励+探索派遣两项全成才算成功 |
| starrail_daily_parser | March7th `logs/YYYY-MM-DD.log` | 提取「累计分数 X/500」活跃度计数 |
| zzz_daily_parser | OneDragon `.log/log.txt` | `指令[任务] 执行成功/失败`，10 项 KEY_TASKS |
| ok_ww_daily_parser | ok-ww `ok-script.log` | 结束语即整体成功，子任务映射 |
| ok_ef_daily_parser | ok-ef `%TEMP%/ok-ef/日常任务/*.txt` | 同日取时间戳最新一份，滤「无」占位符 |
| ok_nte_daily_parser | ok-nte `ok-script.log` | 收尾汇总行 `success/failed/skipped` 优先 |
| whimbox_daily_parser | whimbox 日志 | 8 项任务白名单 + X/Y 计数（必须带 extra 落库） |

## 6. runtime/ 执行层

### 调度与进程管理

- **automation_controller.py**（核心类 `AutomationController`）— 任务级进程管家。`execute_task()`：清理残留进程树 → `_run_prelaunch_flow`（如 WuwaLauncher）→ 拉起脚本 → `_monitor_game` 监控循环：等游戏进程快照 → 轮询报错监控提前止损 → 跟踪 PID/窗口可见性 → 焦点守护 → 收尾返回 `(success, duration, reason)`。内置任务线程心跳 beat 与米哈游维护窗口快速跳过。
- **task_batch_runner.py** — 「一条龙大脑」。`run_task_batch` 串行执行：启动前签到 → 每游戏跳过今日已完成（`_is_game_script_done_today`：脚本行全成功之外还要求 completion_state ∈ {completed, unknown}）→ `_run_single_task` 分派 → 事后判定三兄弟（`_apply_bettergi_verdict` / `_apply_starrail_score_verdict` / `_apply_zzz_activity_verdict`）+ `_verify_script_log_result` 日志复核（只 success→failed 单向）→ 失败统一 8s 重试一次。FailSafeAborted 在此收口为优雅终止整批。
- **process_supervisor.py / window_detector.py** — 进程发现/查杀（整棵进程树）与窗口-PID 关联。

### 视觉流程引擎

- **foreground_flow_runner.py** — 通用「图像模板 + OCR」流程执行器 `run_flow(flow_key)`：从 flow_configs.json 加载 steps → 启动/复用目标 exe（带 UIPI 权限预检 `_uipi_block_reason`）→ 等窗口（可中断）→ 逐步执行。支持 action：`click_template`（模板/OCR 定位 + 确认策略：disappear 每 2s 轮询 / text_change / none）、`wait_template`、`wait_process`，以及复合动作转发：`zzz_shop_buy`、`monthly_exchange`、`nikki_enter_game`、`starrail_enter_main`、`genshin_enter_main`、`qoder_open_campaign`、`qoder_verify_claim`、`wool_verify_log`。收尾 `close_flow_processes`：按 PID 杀进程树 + 按名兜底清残留（Electron 类必须按名），自身与祖先 PID 永不自杀。
- **background_template_runner.py** — 业务组合层：`run_xm/cj_background`、`run_wool_background`（四家薅羊毛，支持 `not_before` 时间门槛）、`_run_monthly_flow`（月度去重，meta 键 `monthly_flow:<KEY>`）。
- **ocr_click_tester.py** — 感知底座：截图优先 WGC（Windows Graphics Capture）失败回退 pyautogui；OCR 主引擎 RapidOCR（CUDA 需 `GAMEAUTOO_OCR_CUDA=1`），tesseract 兜底；多尺度模板匹配。含两条防护铁律实现：窗口不可用**绝不回退全屏 OCR**（返回空结果重试）、日志污染硬拦截（命中日志特征模式的 OCR 条目一律剔除）。

### 业务流程模块

- **白荆回廊四件套**：`baijing_flow`（启动器→进游戏→连续 5 帧模板命中识别主界面→日常→周常/月度钩子）；`baijing_daily`（视觉版日常：OCR 点「任务」→ 滚动列表逐任务领取 + 各类「前往」子任务自动化：研发室收取/记忆烙痕强化/午后茶憩/四类关卡战斗/友情勋章 → 叶脉联结领取 → 俱乐部每日奖励 → 有猫零售每日免费礼包）；`baijing_shop`（俱乐部商店每周全量购买：扫价格按钮→点最大→买→重扫收敛）；`baijing_cat_exchange`（有猫兑换每月按清单点名购买，主锚商品名、价格仅预算校验，空清单不进商店）。
- **monthly_exchange.py** — 三游戏兑换商店月度采购通用流程（ZZZ 信号残响 / 崩铁余烬 / 原星辰尘）：ESC→商店→导航→**页签强校验**（点完必须等「未选中态」模板消失 + 页签中心亮度校验，崩铁/原神 OCR 认错页签名取相邻两者中点定位；原神另有 `forbidden_texts` 宗室武器拦截）→ 按清单购买 → 逐层 ESC 退回主世界。
- **zzz_monthly_shop.py** — ZZZ 后勤商店采购交互（点商品→确认弹窗 ×N 轮，上限跳过不计失败）。
- **三个游戏启动器**：`genshin_launcher`（复刻 BetterGI 进入方法：直启 YuanShen.exe→点击进入→空月祝福→派蒙图标 2 帧命中）、`starrail_launcher`（复刻 March7th）、`nikki_launcher`（叠纸启动器→登录页→弹窗清理→主界面气泡 2 帧命中）。均默认不接线，app_config 配 `prelaunch_flow` 才启用；GENSHIN_MONTHLY 用 `exe_from_game` 直取游戏本体（**不能**走 BetterGI 的 launcher）。
- **wool_claim_logs.py / qoder_claim.py** — 领取结果核验：MiniMax/TRAE 解析 `%APPDATA%` 日志中 claim 接口 200 响应为唯一真相；Qoder 解析 main.log `[Campaign]` 状态，读不到一律失败（fail-closed）。
- **click_sequence.py** — 点击序列录制（pynput）/回放（窗口相对坐标，窗口移动不怕），可 CLI 独立运行。
- **flow_diagnostics.py** — 失败取证：`record_failure()` 抓当刻窗口截图 + OCR 文本样本 → `flow_failures` 表 + `artifacts/flow_failures/`，自动清 14 天前截图。三铁律：永不抛异常、复用调用方 OCR 结果、窗口不可用不存图。

### 日志监控器（后台线程，偏移量增量读取）

- `script_error_log_monitor`：通用报错关键字监控（March7th 等），只读启动后新增行；
- `ok_ww_log_monitor`：ok 系脚本报错/UI 停滞监控与重启触发；
- `bettergi_log_monitor`：原神委托/派遣完成行 → 双向判定依据；
- `whimbox_log_monitor`：暖暖任务结果块归类（completed/skipped/failed）。

## 9. UI 层

### 桌面 GUI（PySide6 + QML + PyHuskarUI）

- **app/gui.py** 内联初始化（QApplication + HusApp.initialize + Engine + Bridge，不走跨模块导入链——`python -m` 模式下跨模块导入会导致 QML 加载失败）；启动 5s 后后台线程拉起 WebUI；`HangWatchdog` 全程守护。
- **ui/bridge.py（UiBridge）** — Python↔QML 唯一枢纽：82 个 `@Slot`（自动化运行/点击录制/凭据/抽卡/每日进度/签到/设置向导/薅羊毛/WebUI/工具十类），~40 个属性 Change 信号 + `uiEvent` 事件总线 + `toastRequested` 弹通知。后台线程经 Qt 排队信号自动回主线程。**带返回值的 @Slot 必须声明 `result=` 类型**，否则 QML 拿到 undefined 且不报错（历史事故）。
- **Main.qml** — HusWindow 1400×900 + 侧边栏 11 项 + 内容区 11 个异步 Loader（`active: ... || xxEverLoaded`，切过即永不卸载——因此每个视图的后台线程必须 daemon + 网络带 timeout）。
- **凭据输入必须用 `components/CredentialInput.qml`**（默认掩码 + 显隐按钮），禁止裸 HusInput 收 token/cookie。
- **ui/flet_app.py**（6918 行）旧 Flet UI 已暂停维护，无 caller，仅作回退。

### WebUI（webui/，FastAPI，仅绑 127.0.0.1:60171）

五个路由模块（auth/automation/daily/wool/clickseq）+ 原生 JS 单页五个标签页；PBKDF2 鉴权（20 万轮，DPAPI 落盘）+ 12h token；`/api/logs` 增量游标 + WebSocket 日志流；同进程经 `get_active_bridge()` 读 GUI 状态、共享 `AutomationController` 单例。定位是远程查看/触发的 GUI 子集。

## 10. 鲁棒性设计（事故驱动的防护清单）

| 防护 | 触发场景 | 机制 |
|---|---|---|
| 日志队列化 | 盘 IO 卡住不阻塞业务线程 | GameAutomation logger 只挂 QueueHandler，QueueListener 消费写盘 |
| 读超时 | USB/机械盘读日志挂起 | `read_file_with_timeout`（默认 10s），超时放弃本轮下轮重试 |
| 任务心跳看门狗 | 任务线程卡死（主线程心跳正常时旧机制无感） | >600s 无 beat → dump 栈 + 置停止 + 杀进程树 |
| 主线程看门狗 | GUI 冻结 | >15s → faulthandler 全线程栈到 watchdog_main_thread.log |
| pyautogui fail-safe 收口 | 鼠标在 (0,0) 触发 FailSafeException | `_pyautogui_click_guarded` 转中文异常，批次优雅终止不崩溃 |
| UIPI 权限护栏 | 本程序普通权限 + 游戏管理员权限 → 点击静默无效 | `run_flow` 预检双方 TokenElevation，直接报可行动错误 |
| OCR 全屏回退禁令 | 窗口不可用时 OCR 拍到桌面/日志文件误命中 | 传了 hwnd 取不到区域 → 返回空结果重试，绝不退化全屏 |
| 日志污染拦截 | 截图里出现 auto_runner.log 文字被当成界面文字 | `_check_log_contamination` 剔除命中日志特征模式的 OCR 条目 |
| 收尾 finally 兜底 | 任务异常穿透导致不发邮件不关机 | 邮件/关机/状态复位全在 `_run_automation_backend` 的 finally |
| 长等待可中断 | 用户点停止后 45s 才生效 | 所有等待传 `stop_check`，轮询粒度 0.25s（个别旧路径未接线） |
| 单实例锁 | 多开竞争 | msvcrt 文件锁，崩溃由 OS 释放 |
| 失败取证 | "步骤没匹配上"无法回看 | record_failure 截图+OCR→flow_failures 表，`tools/flow_failure_report.py` 聚合 |
| optional 假成功防线 | optional 步骤找不到元素直接跳过报 ✅ | 规则：optional 点击后必须跟非 optional 验证步；末步日志核验 fail-closed |
| 维护日动态补跑 | 版本更新维护空跑 | 官方公告解析窗口→跳过；开服+5min 动态补跑队列（最多 3 次） |

## 15. 开发约定速查（详见 AGENTS.md）

1. **改代码前写小计划**：目标文件/符号、假设、第一步验证；首个实质编辑后立刻跑最窄验证（py_compile / 对应回归）。
2. **新增依赖** → requirements.txt + dependency_manager 双登记。
3. **新 UI/数据流写 GameAutomation logger**，不落明文凭据。
4. **解析器产出必须带 `extra={current,total}` 且有落库路径**，否则统计永远拿不到。
5. **判定任务名必须与数据源精确一致**（zzz 是「活跃度奖励」不是「活跃度」）。
6. **`@Slot` 带返回值必须写 `result=`**；凭据输入必须用 CredentialInput。
7. **`_connect()` 是 contextmanager**；WorkflowDB 保持 WAL；禁止裸调 `pyautogui.click`。
8. **optional 步骤后必须有非 optional 验证**；日志核验 fail-closed，绝不假成功。
9. **不硬编码绝对路径**（用 settings/paths.py）；抽卡数据一律走 SQLite。
10. **新建 Electron 应用流程前先测模板误命中再定阈值**（生效阈值 = 列表最小值）。
11. **驱动游戏内流程的任何脚本必须与 GUI 同权限（管理员）运行**。
12. 数值类结论（完成度/活跃度）必须实跑 API 或查库取证，禁止凭代码推断。
